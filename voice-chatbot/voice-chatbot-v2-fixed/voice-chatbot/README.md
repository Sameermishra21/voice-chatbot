# 🎙️ Online Voice-Enabled Chatbot using Speech Recognition and Deep Learning

Open the website, click the **🎤 microphone**, allow microphone access, ask a question out loud and click **⏹ stop**.
The app converts your speech to text, classifies the intent with an **Embedding + Bidirectional LSTM** neural network,
shows the **Recognized Speech**, **Detected Intent**, **Confidence** and **Chatbot Response**, and can read the answer aloud.

There is **no audio-file upload** – the browser microphone is the only input.

```
Microphone ─► Browser records live (Streamlit st.audio_input, 16 kHz WAV)
      ─► Speech-to-Text (Google Web Speech API via SpeechRecognition) ─► recognized text
      ─► Tokenize ► Pad ► Embedding ► BiLSTM ► Dense ► Dropout ► Softmax ─► intent + confidence
      ─► response from intents.json ─► shown on the page ─► 🔊 browser Text-to-Speech
```

**Live deployment:** Streamlit Community Cloud (free, HTTPS) – see §4.
An alternative FastAPI + HTML/JavaScript version of the same app is also included (§5).

## 2. Run locally on a Mac

Requirements: **Python 3.11 or 3.12**, Chrome or Safari, internet (for speech-to-text).

```bash
cd voice-chatbot
python3 -m venv .venv              # use python3.11 if python3 is 3.13
source .venv/bin/activate
pip install --upgrade pip
pip install -r requirements.txt

streamlit run streamlit_app.py
```

The browser opens **http://localhost:8501** → click the 🎤 microphone → **Allow** → speak → click ⏹ stop.

Optional:
```bash
pytest -q                          # 32 automated tests
python tests/test_cases.py         # 15 demo test cases table
python backend/train_model.py      # retrain after editing intents.json
```

If macOS never shows the permission prompt: **System Settings → Privacy & Security → Microphone → enable Chrome/Safari**, then reload.

## 3. Model summary

| Item | Value |
|---|---|
| Dataset | 18 intents (17 college topics + `out_of_scope`), 478 patterns (`backend/intents.json`) |
| Split | stratified 80/20 → 382 train / 96 validation (for evaluation); final model retrained on all 478 |
| Vocabulary | 390 tokens (incl. `<PAD>`, `<OOV>`), max length 12 |
| Architecture | Embedding(390→64, mask_zero) → BiLSTM(64+64) → Dense(64, ReLU) → Dropout(0.5) → Dense(18, Softmax) |
| Parameters | 100,434 |
| Training | Adam (lr 1e-3), sparse categorical cross-entropy, batch 16, early stopping (patience 25) |
| Result | **train acc 99.74 %, val acc 80.21 %, train loss 0.066, val loss 0.746** (best epoch 14 of 39) |
| Off-topic rule | `out_of_scope` predicted, **or** topic words unknown and only filler words known (e.g. “tell me about taj mahal”) → “Sorry, I can only help with college-related questions…” |
| Low-confidence rule | confidence < 0.60 **or** no known words → “I'm not sure I understood that. Could you please say it again?” |

## 4. Deploy publicly – GitHub + Streamlit Community Cloud (free, HTTPS)

### Step A – Put the code on GitHub (no Terminal needed)

1. Sign in at **https://github.com** (create a free account if needed).
2. Click **+** (top right) → **New repository**
   - Repository name: `voice-chatbot`
   - Visibility: **Public**
   - Leave “Add a README” **unticked** → **Create repository**.
3. On the empty repository page click the link **“uploading an existing file”**.
4. In **Chrome**, open the unzipped `voice-chatbot` folder in Finder, select **everything inside it**
   (`backend`, `frontend`, `tests`, `streamlit_app.py`, `requirements.txt`, `README.md`, …) and drag it into the upload box.
   Wait until every file is listed (the `backend/chatbot_model.keras` model must be there).
5. Click **Commit changes**.
6. Check the repository shows `streamlit_app.py` and `requirements.txt` **at the top level** and a `backend/` folder containing `chatbot_model.keras`.

*(Terminal alternative:)*
```bash
cd voice-chatbot
git init && git add . && git commit -m "Voice-enabled chatbot"
git branch -M main
git remote add origin https://github.com/<YOUR_GITHUB_USERNAME>/voice-chatbot.git
git push -u origin main          # password = a GitHub Personal Access Token
```

### Step B – Deploy on Streamlit Community Cloud

1. Go to **https://share.streamlit.io** → **Continue with GitHub** → authorise Streamlit.
2. Click **Create app** → **Deploy a public app from GitHub** (“Yup, I have an app”).
3. Fill in:
   - **Repository:** `<YOUR_GITHUB_USERNAME>/voice-chatbot`
   - **Branch:** `main`
   - **Main file path:** `streamlit_app.py`
   - **App URL:** choose a name, e.g. `akarsh-voice-chatbot`
4. Click **Advanced settings** → **Python version: 3.12** (or 3.11) → **Save**.
   *(TensorFlow 2.21 is tested on 3.11/3.12.)*
5. Click **Deploy**. The first build installs TensorFlow and takes about **5–10 minutes**; progress is shown in the log panel.
6. Your live site: **`https://<your-app-name>.streamlit.app`** – HTTPS is automatic, so the microphone works.

Updating: any new commit to `main` on GitHub redeploys automatically.
An app with no visitors for several days goes to sleep; opening it shows “Yes, get this app back up” – click it and wait ~1 minute.

### Troubleshooting the deployment
| Symptom | Fix |
|---|---|
| Build log: “No matching distribution found for tensorflow” | Python version is too new → ⋮ → **Settings** → Python 3.12 (redeploy) |
| “Could not load the trained model” | `backend/chatbot_model.keras` was not uploaded – upload it to the `backend` folder |
| Mic icon does nothing / permission denied | Click the 🔒 icon in the address bar → allow microphone → reload |
| “speech recognition service is unavailable” | Temporary problem reaching Google – try again |
| App restarts with “resource limits” | Reboot from ⋮ → **Reboot app** |

## 5. Alternative version: FastAPI + HTML/JavaScript

`backend/app.py` + `frontend/` implement the same pipeline with a custom web page
(Web Audio API recording, `POST /process-audio` JSON API):

```bash
uvicorn backend.app:app --host 127.0.0.1 --port 8000     # open http://localhost:8000
```

| Method | Path | Purpose |
|---|---|---|
| GET | `/` | chatbot web page |
| GET | `/health` | server / model status |
| POST | `/process-audio` | multipart field `audio` = browser WAV → `{recognized_text, intent, confidence, response}` |
| POST | `/predict-text` | `{"text": "..."}` → model only (testing) |

It can be deployed anywhere Docker runs (see `Dockerfile`).

## 6. How browser microphone permission works

- Browsers allow microphone access (`getUserMedia`) only on **secure pages**: `https://…` or `http://localhost`.
  Streamlit Community Cloud serves every app over HTTPS, so the microphone works on the live site.
- The **first** click on the microphone shows *“Allow <site> to use your microphone?”*. The choice is remembered **per site**.
- If you clicked **Block**: click the 🔒 icon in the address bar → allow microphone → reload.
  Safari: **Safari → Settings → Websites → Microphone**.
- macOS also has a system switch: **System Settings → Privacy & Security → Microphone**.
